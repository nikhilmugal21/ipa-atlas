# IPA Atlas API

**A runnable, local-first REST API and interactive browser reference for articulatory phonetics.**

![status](https://img.shields.io/badge/release-1.0.0-136f63)  **FastAPI · Python 3.10+ · no paid API keys**

IPA Atlas helps undergraduate/postgraduate linguistics students look up individual IPA phones, understand **where and how a sound is produced**, compare articulations, analyse IPA transcription strings, examine labelled examples, and optionally browse language-specific phoneme inventories.

## What is implemented

- **Every one of the 107 basic official IPA segmental letter symbols**: 59 pulmonic consonants, 10 non-pulmonic consonants, 10 'other' consonants and 28 vowels.
- **31 chart diacritic entries** and independent **stress, quantity, intonation, 19 tone/word-accent notation entries**. An ejective marker and tie-bars are also represented.
- **8 illustrative tied affricates** (such as `t͡ʃ`, `d͡ʒ`, `t͡s`) beyond those 107 basic symbols.
- Descriptions of **active/passive articulators, manner, voicing and airstream**; tongue height, backness and lip rounding for vowels.
- **Articulatory exercises for every basic sound**, *explicitly labelled as constructed, not attested words*. A curated small selection of illustrative lexical transcriptions, including Hindi, Marathi, Bangla, Malayalam, Gujarati, Tamil, English, and examples from other languages. Lexical transcriptions can vary by dialect; they are not a fully peer-reviewed phonetic dictionary.
- Analysis of symbol sequences and combinations such as `[t̪ʰaːmiɻ]`, `/ˈkæt/`, `[d͡ʒʌd͡ʒ]`, `[pʼa]`, `[mǎ]`.
- **Phone comparison** (`[t]` vs `[d]` differs in voicing; `[t]` vs `[ʈ]` differs in place).
- Optional **CMU Pronouncing Dictionary US-English pronunciation lookup** with approximation from ARPAbet to broad IPA, clearly stating the absence of syllabification and syllable-level stress positioning.
- Optional **PHOIBLE CSV importer** with variety- and source-specific inventory retrieval (SQLite; no internet or bundled third-party dataset).
- Source metadata, links and important reuse/copyright notices.
- Built-in browser UI at `/`, autogenerated OpenAPI specification and Swagger docs at `/docs`.

**This is an actual implementation, not a wireframe.** It runs without external network access after dependencies are installed.

## Quick start (macOS / Linux)

```bash
cd ipa_atlas_api
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn ipa_atlas.main:app --reload
```

Then open:
- Student interface: <http://127.0.0.1:8000/>
- Interactive API documentation: <http://127.0.0.1:8000/docs>
- Full JSON symbol chart: <http://127.0.0.1:8000/v1/chart>

On Windows, activate `.venv\Scripts\activate` instead.

### Install optional US-English lookup

```bash
pip install -r requirements-optional.txt
```

The optional `cmudict` Python distribution carries its **own GPLv3+ wrapper licensing terms**; it is not necessary for core features. The original CMU lexical dataset has its own licence. See [THIRD_PARTY.md](THIRD_PARTY.md).

## API examples

### 1. Choose a symbol and read exactly how it is produced

```http
GET /v1/sounds/describe?symbol=ʈ
```

The response contains `symbol`, `name`, `category`, `place`, `manner`, `voicing`, `airstream`, `description`, `articulation`, `source`, and `examples`.

```bash
curl -G 'http://127.0.0.1:8000/v1/sounds/describe' --data-urlencode 'symbol=ɲ'
```

### 2. Examine a modified phone

```bash
curl -G 'http://127.0.0.1:8000/v1/sounds/describe' --data-urlencode 'symbol=t̪ʰ'
```

The output gives the base phonetic classification and explains dentalization and aspiration separately.

### 3. Identify a transcription's segmental structure

```bash
curl -X POST 'http://127.0.0.1:8000/v1/analyze' \
  -H 'Content-Type: application/json' \
  -d '{"transcription":"[t̪ʰaːmiɻ]"}'
```

Returns the IPA segment tokens, attached diacritics, notation type (phonemic/phonetic/plain), offsets in NFD-normalised text, unrecognised characters and warnings. It **does not** claim to infer the phonemic inventory of the language.

### 4. Compare two phones

```bash
curl -X POST 'http://127.0.0.1:8000/v1/compare' \
  -H 'Content-Type: application/json' \
  -d '{"a":"p","b":"b"}'
```

### 5. Show examples in a chosen language

```bash
curl -G 'http://127.0.0.1:8000/v1/examples' \
  --data-urlencode 'symbol=ɳ' \
  --data-urlencode 'language=Marathi'
```

Examples include clear `type` fields: `illustrative_lexical_example`, `illustrative_reference`, or `constructed_articulatory_drill`. Only the first type is intended as a lexical illustration, and it still needs dialect-specific verification.

### 6. English word lookup (optional)

```http
GET /v1/transcribe/english/phonetics
```

Uses the optional CMU dictionary, not any generative AI model. Its broad converted output has **no IPA stress markers** and should not be mistaken for a narrow pronunciation. Lexical vowel stress levels are reported separately in ARPAbet ordering.

## Optional PHOIBLE integration

1. Download a PHOIBLE CSV dataset from [the official PHOIBLE download page](https://phoible.org/download) or a compatible version of the PHOIBLE development `phoible.csv` with `InventoryID`, `LanguageName`, `Phoneme` and `SegmentClass` columns.
2. Use a **pinned released version** for reproducible academic research and record its version and licensing details in your deployment documentation.
3. Import your copy:

```bash
python scripts/import_phoible.py /path/to/phoible.csv
```

This creates a local read-only query database in `data/phoible.sqlite`. Original inventory IDs, ISO639-3 codes, Glottocodes, variety labels and source references are preserved.

```http
GET /v1/inventories/status
GET /v1/inventories?language=Hindi
GET /v1/inventories?iso6393=hin
GET /v1/inventories/123
GET /v1/attestations?symbol=ɳ&language=Hindi
```

**Important:** PHOIBLE catalogues analyses of *phonemes* in documented language varieties. A listed phoneme is NOT a recorded pronunciation of a specific word. Inventories can disagree and must not be silently merged into a universal language inventory. PHOIBLE data is **not** bundled.

## Explanation of phonetic coverage

A **phone** is an actual speech sound, usually represented in square brackets: `[p]`. A **phoneme** is a contrastive linguistic unit, represented in slashes: `/p/`. One phoneme can have multiple phonetic realisations, and IPA symbols describe qualities of speech, not every distinction that matters in a given language.

The claim of **107 complete core symbols** applies to the **basic segmental letter inventory shown on the IPA chart**, *not* the impossible claim that every humanly possible sound is already listed as one independent glyph. An open-ended number of precise transcriptions can be made using diacritics, combinations, suprasegmentals and special-purpose notation. The project is not intended to exhaust every Unicode IPA or Extended IPA construction.

### Known limitations and future improvements

- Not a speech recognizer: **audio → forced alignment / spectrograms** are not implemented.
- Not general orthography → IPA: there is only an optional US English lexical dictionary, and no automatic grapheme-to-phoneme engines for the seven languages.
- Most rare sounds have clearly labelled **constructed articulatory exercises**, not fabricated lexical examples.
- Manual articulatory descriptions describe typical configurations. Exact realisations can differ substantially by language and individual speaker, especially clicks, rhotics, laryngeals and vowels.
- Optional PHOIBLE importer currently supports the `phoible/dev/data/phoible.csv` **flat format**, not CLDF `values.csv` plus companion tables. See sources for alternatives.
- Transcription parser is a pragmatic educational grammar. It does not infer syllables or detect all contextual allophones, all tie-bar layouts or every extIPA mark.
- Official IPA recordings cannot be redistributed freely with the project. The UI does not pretend to play isolated IPA symbols using generic browser text-to-speech.
- For research publication, verify selected lexical examples against a documented language/dialect, source and speaker, rather than treating the examples in this demo as normative transcriptions.

## Relationship to the earlier LinguaGloss API

This project can run as an independent service at `:8000` or be **mounted as a subapplication** in an existing FastAPI system; the earlier Leipzig Glossing Rules API does not need to be rewritten. See `INTEGRATION.md`.

The repository also includes a ready-to-deploy Streamlit UI (`streamlit_app.py`). **This is an interactive app, not an externally addressable FastAPI REST service.** It imports the same phonetics library and runs without a second server.

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```
